# Профили маршрутизации и схемы ссылок

Приложение поддерживает обмен профилями маршрутизации через ссылки (deeplink). **Код обрабатывает любую ссылку независимо от схемы**: распознавание определяется не схемой, а структурой ссылки — хостом `routing` и командой в пути.

## Формат ссылки

```
<любая-схема>://routing/{add|onadd|off}[/{base64-JSON-профиля}]
```

- Схема может быть **любой** — `imsel://`, `happ://`, `любое://`, имя стороннего клиента и т.д. Исключение: `http://` и `https://` (обычные веб-адреса не распознаются, даже если в пути встречается слово «routing»).
- Команда:
  - `add` / `onadd` — импорт профиля из base64-payload (после подтверждения пользователем);
  - `off` — профиль-«пустышка» (выключение, без payload).
- Payload — Base64 (стандартный или URL-safe) JSON-профиля маршрутизации.

### Примеры

| Ссылка | Поведение |
|---|---|
| `imsel://routing/onadd/eyJHbG9iYWxQcm94eSI6InRydWUifQ==` | Импорт профиля (наша схема) |
| `happ://routing/onadd/eyJHbG9iYWxQcm94eSI6ImZhbHNlIn0=` | Импорт того же формата — схема другая, обработка идентичная |
| `любое://routing/onadd/<base64>` | Любая иная схема — работает так же |
| `someclient://routing/add/<base64>` | Тоже работает (команда `add`) |
| `imsel://sub/e1/<base64>` | НЕ профиль — offline-раздача подписки (другая функция) |
| `https://example.com/routing` | НЕ распознаётся (веб-ссылка) |

### Экспорт

Экспорт профиля всегда выполняется в собственной схеме приложения:

```
imsel://routing/onadd/<base64-JSON>
```

Экспортировать можно из экрана «Профили маршрутизации» (поделиться ссылкой или QR-кодом). Экспорт из другого клиента в его схеме остаётся импортируемым в IMSEL без изменений.

## Способы передачи профиля

1. **Ссылка** — открытие из мессенджера/браузера (для `imsel://` зарегистрирован intent-filter), вставка из буфера обмена, ручной ввод в «Профили маршрутизации».
2. **QR-код** — сканирование на экране «Профили маршрутизации».
3. **HTTP-заголовок ответа подписки** — сервер подписки может передать deeplink-профиль в заголовке ответа (или первой строкой комментария в теле). Профиль применяется после подтверждения.

## Что содержит профиль

JSON-профиль — высокоуровневая обёртка маршрутизации:

- 6 списков доменов/IP: Direct/Proxy/Block × Sites/Ip;
- порядок применения (`routeOrder`, по умолчанию proxy → direct → block);
- параметры DNS: удалённый/локальный резолвер (DoH/DoU, произвольные провайдеры — AdGuard, NextDNS и др.), hosts-записи, fake DNS;
- `globalProxy` — проксировать всё без исключений;
- URL гео-баз (geoip/geosite);
- `domainStrategy`.

Импорт создаёт **новый профиль** в IMSEL (дефолтный не затрагивается). Правила профиля полностью заменяют набор правил создаваемого профиля; DNS-записи добавляются в пользовательский список. Ключи JSON поддерживаются в PascalCase (`DirectSites`) и camelCase (`directSites`).
