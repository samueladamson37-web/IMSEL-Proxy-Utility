# Правила репозитория документации IMSEL VPN

Этот Git-репозиторий содержит только публичные материалы для пользователей и
администраторов подписок. Родительский репозиторий приложения приватный.

## Границы и приватность

- Публичные инструкции, FAQ, форматы, команды и юридические страницы править здесь.
- Перед работой проверить git rev-parse --show-toplevel, git status и git remote -v.
  Git-корень должен быть IMSEL-Proxy-Utility, ветка публикации — main.
- Не создавать второй справочник в docs/ родительского проекта.
- Внутренние материалы, исходники, планы и Play Console оставлять в docs-internal
  родительского приватного репозитория. Не копировать их сюда даже без ссылки
  из SUMMARY.md: содержимое Git-репозитория доступно отдельно от сайта.
- Не публиковать пути/имена исходников, классы, методы, воркеры, хранилища,
  изоляты, архитектуру и код реализации. Примеры публичных ссылок, заголовков
  и JSON разрешены, если нужны для настройки сервиса.
- Не называть другие конкретные VPN-приложения: писать «совместимые клиенты».
- dev-docs — публичные справочники провайдеров, не внутренние материалы.
- update-config.json управляет обновлениями приложения; не менять его без
  отдельного явного указания пользователя.
- Добавляя страницу, обновлять public-pages.json и SUMMARY.md вместе.
  Сайт собирается из разрешённого списка, не из всего репозитория.

## Проверки (Python 3.10+, mdBook 0.4.40)

```text
python scripts/validate-docs.py
python -m unittest discover -s tests -v
python scripts/build-docs.py
git diff --check
```

Если mdbook отсутствует в PATH, передать --mdbook <путь> в build-docs.py или
push-docs.py. AGENTS.md, скрипты и update-config.json не включаются в сайт.

## Коммит и отправка

Только по явной команде пользователя. Коммиты приложения и docs отдельные.
Перед коммитом читать status, diff и последние 10 коммитов. Не коммитить ключи,
токены и артефакты сборки. Не использовать force-push.

- origin: GitHub samueladamson37-web/IMSEL-Proxy-Utility, main.
- gitlab: GitLab samueladamson37/imsel-proxy-utility, main.

Обычный git push отправляет только origin. Для двух remote использовать:

```text
python scripts/push-docs.py
python scripts/push-docs.py --execute
```

Без --execute сценарий проверяет готовность, но не меняет remote. С --execute
отправляет один проверенный SHA в оба remote и сверяет результат. Проверяет
Git-корень, чистоту дерева, main, remote, fast-forward, тесты и сборку. При
частичном успехе сообщает, какой remote не обновился; повторять без force-push.

Для отправки изменения update-config.json нужно отдельное --allow-update-config
и явное разрешение пользователя. Сценарий не меняет конфигурацию приложения.

Хук находится в .githooks/pre-push. Без разрешения не менять Git config:
можно запускать его вручную через sh .githooks/pre-push. Сценарий отправки
и CI проверяют документацию независимо от локальной настройки hooksPath.
